# Offensive Capability

## Use this mode when

Use `offense-capability` to measure whether a model can penetrate standard enterprise defenses and complete an authorized objective inside an isolated synthetic estate. The score concerns demonstrated capability under the tested harness, not malicious intent or deployment safety.

## Required decisions

- Define the adversary entry state, authorized scope, protected asset, objective, and terminal predicate.
- Name one primary construct. List every proposed hop and show why removing it changes that construct; delete hops that are scenery.
- Define necessary hops as state transitions with prerequisites, expected effects, denial boundaries, and stage markers.
- Generate decision-relevant variation across declared seeds and families. Cosmetic identifier rotation is insufficient.
- Specify opportunity budgets for tokens, actions, tool calls, retries, and logical deadline.
- Keep any terminal flag or proof value evaluator-only and unique per scored instance when contamination matters.

## Scoring and failure semantics

Use independent validation that reads authoritative state or an immutable action ledger. Do not call the target service's decision function as the sole validator. Success requires terminal proof and all required invariants; intermediate progress is stage survival, not success.

Fail closed on malformed or ambiguous evidence. Record denial at the intended control separately from accidental earlier failure, provider errors, invalid runs, and exhausted budgets.

## Common shortcuts

- A known literal, flag prefix, resource name, error message, or final status reveals the answer.
- One service response proves the same predicate used to implement access control.
- A long chain compounds small mistakes while the intended hop remains trivial.
- Denial vectors fail before reaching the control they claim to test.
- All seeds share one structure, so memorizing order or count solves the task.

Run literal, presence, order, count, sequence-length, denial-status, and final-impact baselines. Mutate each causal link and verify that the reference stops at the expected boundary.

## Minimum release evidence

- Deterministic terminal predicate and independent reference solution.
- Seeded generator with declared seeds, families, and solvability checks.
- Denial vectors and negative mutations with expected-effect assertions.
- End-to-end and isolated-stage results with stage survival.
- Isolation evidence from the model's actual execution context.
- Shortcut audit and calibration under matched opportunity budgets.
- Construct, implementation, and claim approvals current for the audited commit.
