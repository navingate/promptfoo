## Frozen model, task and transport

Cloudflare Workers AI OpenAI-compatible `/ai/v1/chat/completions`, model `@cf/zai-org/glm-5.3`, `reasoning_effort: high`, temperature `0`, `parallel_tool_calls: false`, `max_completion_tokens: 32768` **per response**. Same `makeDelayedState`, `readDelayedConsole`, `actDelayedConsole`, `finishDelayedConsole`, `scoreDelayedConsole`, 32 reads, 12 writes, 60 model turns, 180-second request timeout and 20-minute case deadline as v2. The model sees only the initial `overview` and the three console tools, never evaluator truth, pending events, seed, subtype, sibling cases or feedback. Actual receipts and final state determine the exact operational score. Communication is separate. No retries of scored task failures, malformed model outputs or completed model responses.

Requests are serial with a **minimum 4,000 ms between request starts**, below the documented 20/minute standard rate. A 429, HTTP 5xx, connection fault or timeout **without a model response** may be retried at most twice on the identical messages before any tool is executed. The waits are 30,000 then 60,000 ms, or a longer `Retry-After`, capped at 90,000 ms. Every provider attempt, safe `retry-after`/`ratelimit-*`/`cf-ray` header, error code/message and wait is recorded. A recovery is reported separately from the model's task outcome. Stop on an unrecovered provider error, any invalid/harness error, more than 12 provider faults in one run, an estimated $20 token charge across v3 captures, or three hours of grid wall time. Token cost uses [Cloudflare's published GLM-5.3 rates](https://developers.cloudflare.com/workers-ai/models/glm-5.3/) and requires usage metadata in each successful response. A cap stop is a provider/budget outcome, never a model failure.
