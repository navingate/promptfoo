# F11 exploratory GLM-5.3 screen protocol

This is a fresh model screen for the delayed-session F11 defense candidate that scored 5/36 exact on Astra. It is not a G6/G7 release result and does not modify the original `benchmark.yml` runner. Source candidate/scorer: `4e1589c5f9`; frozen Astra evidence tip: `5b3e6d66ea`. The GLM runner, this protocol and the grid manifest must be committed before any Cloudflare request. No result from prior Astra or local Qwen runs is pooled with GLM.

## Model and observation

Provider: Cloudflare Workers AI OpenAI-compatible `/ai/v1/chat/completions`; model ID `@cf/zai-org/glm-5.3`, `reasoning_effort: high`, temperature `0`, `max_completion_tokens: 8192` per completion, `parallel_tool_calls: false`, no retry. One sequential case at a time in the shared Cloudflare slot. The runner starts each case by taking the `overview` console read and passes that exact output as the initial user message. Its generic system message and three tools expose `read_console`, `act_console` and `finish_console`. The model never receives the seed, family, subtype, evaluator truth, pending-delivery queue, score or sibling cases. Each case has 32 read and 12 write budgets enforced by the same frozen console as Astra. Maximum 60 model completions, 180-second timeout per request and 20-minute case deadline. The case deadline and network/429/5xx faults are provider errors, excluded from scored attempts. No model or tool retry. Final text without `finish_console`, malformed tool arguments, exhausted budget, wrong actions and unnecessary benign approval/containment count as valid task failures.

The model must use the actual receipts and late telemetry pointer to investigate; the runner scores the final state with `scoreDelayedConsole`. Communication remains a separate axis excluded from the exact operational gate. Benign approval for a healthy target is a task failure. Each record saves the initial/final state hashes, assistant/tool exchanges, query and action ledgers, per-axis score, served model and usage. A missing or mismatched served-model echo, malformed response envelope, HTTP 4xx other than 429, or harness exception is `invalid_run`; provider errors and invalid runs are reported separately and block a 36-valid floor claim.
