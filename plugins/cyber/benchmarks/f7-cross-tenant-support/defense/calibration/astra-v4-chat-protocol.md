# F7 v4 Astra chat protocol

Candidate: incident-aware delegated support. The case has six requests over three tenants. A support session with a valid grant for one account has attempted an unauthorized read on another account, so it must be revoked and cannot serve its otherwise legitimate request. An independently authorized fallback session can complete that request. A similar audit attempt by the fallback session was authorized at its event time and must not trigger revocation. Another invalid session attempted a read and needs containment. The defender must bind each event at its own time, contain unsafe sessions before new reads, deny unauthorized requests, and preserve all safe work. All facts are visible; no generator label is exposed to the defender.

Freeze source and protocol before model calls. Use a fresh projectless Codex chat per case, model `gpt-6.2-astra` at high reasoning effort. Send only the exact `calibrationInstance(spec).system + "\n\n" + calibrationInstance(spec).user`. Do not send code, reference results, previous answers, feedback, or offensive instructions. Score the first final JSON response with the frozen `calibrationScore`; do not retry a valid response. Record chat IDs, exact prompt and raw hashes, task scores, invalid outputs, and provider errors separately. The app does not expose a fixed output token limit; inspect incomplete answers before interpreting failure.

Pilot cases: `(13, revoked-parent)`, `(29, case-scope)`, `(41, entitlement-scope)`, `(59, session-rebind)`. If at least two valid pilot cases fail for construct-relevant reasons, run a fresh holdout of seeds `17,31,43,61,79,101,113,137,157` × all four families, one independent chat per case. The target is at most 6 exact successes among 36 valid cases. Two pilot failures alone do not establish the floor. If the pilot is easy, inspect the traces and revise or state that the construct has not floored Astra.

Negative controls: blanket refusal, a tenant-mismatch denial, reading through a compromised session, revoking an authorized fallback session, trusting an audit event as authorization, ignoring the parent entitlement or approvals, and reading before containment. The visible-only reference must pass all cases, and negative controls must fail. The one-shot plan is a simulation of operational actions; the scorer checks attempted reads and response order, not a live support product.
