# F4 v13 observation and field lineage

This task consumes newly generated **synthetic F4 native incidents**, not old F4 offense transcripts. `producer.mjs` creates grants, approval rows, one shared reset, token issuances, and client-scoped protected-call events using the shared F4 authorization and revocation controls. `corpus.mjs` validates each incident before projection. It copies the listed fields unchanged; it does not create an approval, access, or causal link.

| Model-visible source                                    | Native source                                                   | Meaning                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Initial `incident_id`, `protected_scope`, `base_policy` | Incident header                                                 | Published investigation context and base rule.                                                                                                                                                                                                                                     |
| `list_grants` page                                      | `incident.grants[]`                                             | Grant, client, principal, scope, route, issue time, and credential lineage. Pagination is presentation only.                                                                                                                                                                       |
| `get_registry(client_id)`                               | `incident.registry[]`                                           | All entries whose client selector can cover that client; selector and validity facts are copied from native rows. The filter is a declared query, not an authorization verdict.                                                                                                    |
| `get_remediation()`                                     | `incident.remediation` plus the event named by `reset_event_id` | Compromised user, one reset time, revoked grant IDs, password/session reset facts, and native reset event ID.                                                                                                                                                                      |
| `get_events(client_id)`                                 | Client-scoped creation, token, and protected-call events        | A client can have several grants. The caller follows each protected call's `caused_by_event_id` to a token, then the token's grant ID and credential lineage to the grant. The call itself carries neither grant ID nor lineage. Source time and arrival index are both preserved. |
| Tool feedback                                           | Read-only query result or schema error                          | No labels, partial score, or expected finding count.                                                                                                                                                                                                                               |

Only `evaluator/keys.jsonl` contains the target labels. The evaluator computes them from the native state through the F4 policy and the token→call chain. The independent reference queries the model-visible sources and uses a separately implemented authorization join. The manifest binds native, projected, and key bytes plus the producer, projection, prompt, tool, scorer, shortcut, and independent reference code hashes.

Observation categories: the system/user prompts and query results are model-visible; the checked-in native file, evaluator key, source code, manifest, tests, score, and private model trace are **not staged** to the model. No task-specific environment value or external artifact is exposed. A blind chat with unrestricted repository file access is an excluded pilot unless its tool transcript shows it followed the read-only interface only.
