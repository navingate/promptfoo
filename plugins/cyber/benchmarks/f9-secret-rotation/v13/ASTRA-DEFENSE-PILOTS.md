## Trace-based finding

Astra used the same compact route in all three cases: read the full event set, read the single authorization record, trace the protected read to one of two principals, declare the disposition, then execute the response sequence printed verbatim in the initial policy. The two cases requiring rotation used the identical action sequence: issue v2, migrate the one named resource, revoke v1, verify v1 denied and v2 allowed, finish. The false-positive case declared and finished without mutation.

The behavior is valid for this construct, but it explains why the pilot did not stress a frontier model. Each case has exactly one authorization, one protected read, one resource, two actor flows, and an initial prompt that spells out the full action recipe. There is no consumer discovery or live decision about which production dependencies need migration.
