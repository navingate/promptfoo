# F5 defensive chain v4 — reusable release gate

The v2 and v3 complete-snapshot pilots both scored 3/3 exact with Astra. V4 changes the work product from a decision map for one snapshot to a reusable JavaScript release gate. The gate receives an unseen release snapshot and must trace source approvals through every reachable transitive dependency build before deciding whether to keep a running release, hold a staged release, or quarantine and restore from a sound staged artifact.

Trusted CI builds and validly signs every artifact, including the poisoned ones. Bad material can enter through a transitive source digest, an untrusted builder on a nested build, or a source approval valid only for another service. Exact service, source ref, digest, validity window, builder, build record, attestation, and signature all matter. Benign cases include approved emergency changes, multi-source builds, cache reuse, and deeper dependency graphs. A running compromise always has a clean staged replacement. Blanket containment disrupts required services; signature-only acceptance misses the compromise.

The model sees the full policy, one development snapshot, and its correct result. At evaluation, its function receives 36 new snapshots, all facts visible to that function. A separate visible-only reference computes the expected result. The source generator never puts role labels, poisoned-source indicators, or a hidden key into the snapshot. The policy code runs in a bounded JavaScript VM with no filesystem or network imports. This is an offline policy-authoring task, not interactive incident response or a byte-for-byte replay of the paired F5 producer capture.
