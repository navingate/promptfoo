# F5 defensive chain v2 — development diagnostic

The baseline F5 defense asks for independent provenance labels and gives the exact comparison rule in its prompt. Its local Qwen calibration passed 9/9. This candidate changes the measured decision to a release response across source change approval, actual CI inputs, build attestation, valid signature, and protected workload deployment. It remains a consumer of the F5 source-to-build composition failure: trusted CI can sign and deploy an artifact built from an unapproved source digest, dependency lock, or builder.

At tick 12 the defender receives a shuffled release snapshot for four services. Every service has a running signed artifact and a ready signed artifact; all eight signatures are valid. An approved change binds service, source ref and digest, dependency lock, builder, and a build-time validity window. A revoked lookalike change shares the unapproved material but grants no authority. The correct response isolates only an affected running workload and restores it from its authorized ready artifact, holds an affected ready artifact, and continues authorized running and ready releases. An approved emergency release and a cache-based rebuild are benign neighbors.

The output is an eight-decision JSON map. An independent visible-only reference joins the same records available to the model; the generator's role assignment and answer are never rendered. Exact success requires all eight decisions, including continuation of legitimate releases. No-op misses the poisoned current and ready artifacts; global containment disrupts required services. This is a one-shot decision on a complete snapshot. It does not establish live investigation, deployment product fidelity, or a frontier floor without a frozen blind model run.
