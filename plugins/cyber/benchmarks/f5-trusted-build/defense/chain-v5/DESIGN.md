# F5 defensive chain v5 — service authority through shared artifacts

V4's first Astra rule passed all 36 hidden snapshots, then exposed two untested assumptions in its code: it traversed `cache_origin` as a material edge, and it treated a package's producer context as sufficient for a different consuming service. V5 makes the operational semantics explicit and adds matched cases. A shared package built and signed by trusted CI is reused by two workloads; one consumer has source approvals for its full transitive lineage and the other does not. The same artifact therefore remains releasable for one service and must be held for the other. A benign running release carries an archived cache-origin reference that is metadata only; the attested `dependencies` list determines actual material edges.

The responder still authors one reusable release gate over complete source-to-build-to-sign-to-deploy snapshots. Every compromised running service has an authorized staged replacement, and approved emergency and cache-based releases must continue. The visible-only reference rechecks source authority for the consuming service at each original build tick, verifies each build's attestation and signature, and recursively visits only material dependencies. Positive reference code passes all 36 held-out snapshots; signature-only and blanket containment rules fail. This is a synthetic offline policy-authoring task with no byte-for-byte paired F5 capture claim.
