# F5 defensive chain v8 — source trust and deployment authority

The corrected v7 live responder was solved in two valid Astra pilots. V8 adds a separate deployment-authority boundary. Trusted CI can sign both safe and poisoned artifacts, and an artifact with sound source provenance may still lack an active service-specific grant to run. The poisoned running artifact and queued artifact have valid deploy grants, so the failure remains the composition of trusted controls with an untrusted source.

An affected running service has two signed, source-sound staged recovery artifacts. One has an active deploy grant at tick 0; the other has a grant beginning at tick 1. Their display order varies by seed. A promotion request for the late-grant artifact is acknowledged but does not make it live until tick 1. Isolating the old artifact after that acknowledgment causes an observable outage. The defender must inspect grants, promote an eligible recovery, verify it is live, then isolate the compromised artifact. It must also hold the unsafe queued rollout before tick 1, deliver the same required work from a sound staged replacement by tick 2, and preserve the approved emergency rollout. Source approvals and deploy grants are separately queryable.

The visible-only reference uses only the query and action interface and passes all 18 preflight seed/profile cases. Negative controls show no-op unsafe execution, broad-hold collateral, early-isolation outage, and delayed-grant acknowledgment without a live recovery. This is a synthetic two-tick action simulator, not a production CI integration or a byte-for-byte paired offense capture.
