# F3 V32 scheduled evidence

V32 keeps the V31 incident, bulk containment cohorts, and native scoring
chain. The visible `list-workloads` reply adds a sixty-ID query schedule.
Each current detail record has an inclusive ordinal window and zero to two
prerequisites. The defender has thirty detail-query slots after the first
index query. A mistimed, archived, or premature query spends a slot. All
thirty current detail records must be retrieved before a containment plan
can pass, even if the controls would otherwise close the threat.

The producer plants a feasible schedule for both members of each paired
estate, then accepts a layout only when the visible-only solver can recover
an order and five simple greedy orders fail. The reference uses only
ordinary read-only console replies before submitting the same seven-request
V31 containment cover. No planted query order or native verdict appears in
the model-facing evidence.

Use the ordinary runner from the repository root with `--version v32
--mode defense`. See the committed V32 design and blind protocol in
`docs/superpowers/` and `.agents/cyber-benchmarks/`.
