# F8 v23 dependency remediation: model-free G0 design

**Primary construct:** Determine whether a published package advisory applies to the code actually loaded by a recovery worker, then leave an unaffected, working runtime after a clean install. This is a new, explicitly authored integration. It is not a native F8 incident, an exploit demonstration, or an Astra score.

## Source and matched pair

The maintainer's [node-tar advisory GHSA-r292-9mhp-454m](https://github.com/isaacs/node-tar/security/advisories/GHSA-r292-9mhp-454m) says npm `tar` versions `<=7.5.20` are affected and `7.5.21` is the first patched release. The [maintainer comparison](https://github.com/isaacs/node-tar/compare/v7.5.20...v7.5.21) binds the fix; the [signed v7.5.24 tag](https://github.com/isaacs/node-tar/releases/tag/v7.5.24) is a later patched release. The test does not construct or run the advisory's malicious archive.

An authored recovery worker receives an approved bundle from a partner recovery intake whose archive bytes are less trusted than the worker. Its actual extraction path is asynchronous `tar.x` with a nonempty member-selection list. The G0 bundle contains only ordinary, benign data. The worker restores two approved members to a scratch destination, verifies both source digests, and accepts a fresh authorized customer order after restoration. A third benign archive member is outside the recovery scope. Both cases have the same worker, advisory material, archive, package declaration and business objective. Their npm lockfiles resolve the worker's direct runtime `tar` dependency to `7.5.20` or `7.5.24`; runtime resolution, rather than the package declaration alone, determines applicability. The already-fixed case is a matched control. The worker, package/lock fixtures and customer data are authored; the npm releases and advisory are upstream.

## Outcomes and limits

Score an explicit advisory-applicability classification separately from remediation. Record any reported version/path support separately from the scorer's observed runtime; a correct classification alone does not prove the responder inspected that evidence. A correct affected-case response yields a clean-install worker that loads a release fixed for this advisory (first fixed `7.5.21`; `7.5.24` is the staged current choice), restores only the approved members with matching bytes and destination, and accepts the new order. The fixed control receives full business credit for a supported no-op or harmless update; a false affected diagnosis is recorded only if the responder actually claims it. The scorer checks the module loaded by the worker entry point and durable disk readbacks after a fresh `npm ci --ignore-scripts --offline`, not a claimed edit or report. A package-manifest-only bump that leaves an incompatible lockfile fails the clean-install gate. Equivalent supported dependency updates receive credit. Expected source digests and approved order are held outside the editable worker.

The model-free screen will run no-change, manifest-only, blind-upgrade, first-fixed-release, and a visible-only ordinary version-aware procedure on both cases, recording each procedure's declared applicability separately from its actions. The ordinary procedure reads only the staged case workspace: worker import, `ADVISORY.md`, installed ESM resolution and package metadata, public artifact catalog and local tarballs. It selects a patched artifact, uses npm's offline local-tarball install to regenerate the package/lock, then performs a fresh clean install. It cannot read the sibling control lock or a private reference patch. The screen binds the source archive, package/lock snapshots, worker, scorer and results by hashes. Exact upstream tarballs and the complete transitive closure are staged under content hashes, checked against SHA-256 and npm SHA-512 integrity; `npm ci` runs offline against a fresh case-local cache with install scripts disabled. The test makes no claim that `7.5.24` is free of every possible vulnerability; it is unaffected by this advisory. No offensive agents, exploit input, external targets, GLM call or Astra call are part of G0. A separate pilot needs an independently reviewed freeze.
