# F10 v40 dependency-remediation feasibility

**Published maintainer advisory:** [nodejs/undici GHSA-wqq4-5wpv-mx2g](https://github.com/nodejs/undici/security/advisories/GHSA-wqq4-5wpv-mx2g), CVE-2023-45143. It marks npm `undici` versions **below 5.26.2** affected and **5.26.2 or later** patched for retaining a Cookie header across an origin-changing redirect in `fetch`. The issue is conditional on a Cookie-bearing redirect. This fixture does not reproduce the issue, send a redirect, or use an external network target.

This is a disposable, explicitly authored sanctioned-publication client. Its real `publisher.mjs` entry point imports `fetch` from the npm `undici` package, not Node's bundled global `fetch`. It sends an approved protected report and separate approved DOB ETL to an in-process `MockAgent`; `benign-check.mjs` proves both partner receipts and records the package path resolved **from the publisher entry point**. The Cookie header makes the advisory relevant to the client path if a cross-origin redirect were encountered, without manufacturing one in the test.

Two clean-install controls use identical service, test and advisory bytes and the same neutral package name: one npm lockfile resolves `undici@5.26.1`, within the advisory's affected range; the other resolves `undici@5.26.2`, the maintainer-patched release. Both are staged as `cases/workspace`, with no arm name in the model-facing path. Local tarballs match the published registry integrity hashes and let `npm ci --offline` rebuild with no network. The scored task would ask whether this particular advisory applies to the actually loaded runtime and, when necessary, repair the manifest/lock so a clean install resolves an unaffected release while both authorized deliveries still complete. A harmless no-op is valid business behavior for the already-fixed control. Advisory recognition and actual runtime/business outcome are separate axes; changing a text label without changing the resolved runtime cannot pass remediation. A manifest-only version bump also fails clean installation until the lockfile is reconciled.

The v13 native publisher is not an HTTP client; this package issue is not claimed as a native v13 or Promptfoo runtime finding. The HTTP client and its packages are authored for this benchmark. This design awaits independent review of the model-free resolver, lockfile, artifact and benign continuity proof before any Astra call. GLM remains paused.
