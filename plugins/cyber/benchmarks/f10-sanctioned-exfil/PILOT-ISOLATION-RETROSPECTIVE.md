# F10 Astra pilot filesystem-isolation qualification

During v26 prelaunch review, Cyber Benchmark found that the v18, v21 and v23–v25 pilot runners wrote a `launch.json` containing case metadata into the Codex working directory before spawning the model. This includes seed/case index in the earlier versions and explicit `arm` in the rejected first v26 freeze. A model with a permitted or unexpected local file read could have seen that metadata. The model-visible prompt bytes and preserved scores are unchanged, but these prior runs support **prompt-blind with no observed tool use**, not proven strict filesystem isolation of private launch metadata. The first v26 freeze was held before any model call.

A scoped audit of the 21 preserved summary attempts under v18 pilot-v1, v21 pilot-v1/v2 and v23–v25 pilot-v1 found 19 `valid` and two `provider-or-cli-error` records; every `tool_items` value is zero. This is evidence against an observed model tool read in those traces, not proof that all local metadata was inaccessible or that an unrecorded read occurred. V17 and v16 are outside this scoped runner audit. Earlier exact scores, raw files and the v21 stopped-protocol qualification remain as frozen.

The v26 runner now creates separate ephemeral model and host raw directories, asserts the model directory is empty immediately before spawn, and writes private seed/arm launch metadata only after the model process exits. Its raw response/events are retained outside model cwd. Focused tests cover the empty-directory assertion, malformed/incomplete events, and the preregistered rule that complete prohibited tool use is a valid conduct failure with no replacement. This correction applies prospectively to v26 and does not retroactively upgrade the earlier blind-isolation claim.
