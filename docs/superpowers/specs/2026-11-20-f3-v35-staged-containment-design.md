# F3 V35 staged containment design

## Evidence and objective

V33's static quarantine/exception cover passed 12/12 valid high-effort
agentic Astra blind cases. V34 added exclusive current-selector ownership and
passed its 36/36 visible reference gate, but Astra passed 9/9 valid
development pilots. In both, Astra collected all thirty current records in
31 queries, resolved each Job/session authorization with local code, then
computed a safe four-request cover. V34 was retired before holdout.

V35 preserves the native source-to-release-credential, Job, Pod, STS session,
and protected-object chain, approved-work collateral, paired approval flip,
31-query evidence schedule, and exclusive quarantine ownership. It changes
when the four requests must be staged: the defender must commit three bulk
quarantines during the evidence collection, then choose the exception after
the last detail. The user permits this artificial emergency change-board
constraint even though it stretches ordinary enterprise response.

## Alternatives and choice

- Further catalog growth tests input volume and leaves the V34 solver intact.
- A natural-language approval puzzle would change the authorization construct
  and risk inconsistent interpretations.
- **Staged irreversible controls** directly invalidate the observed
  collect-all-then-plan workflow. Choose this as an empirical V35 probe; it
  still requires a full visible-only reference and a development Astra pilot
  before any blind holdout. No floor is claimed in advance.

## Action and query semantics

The four original requests are ordered: three `quarantine-cohort` requests
and one `except-cohort`. The first quarantine must be accepted at query
ordinal **20**, the second at **24**, and the third at **30**. The exception
must be accepted only after the successful thirty-first query. A query
ordinal counts `list-workloads` and every syntactically valid attempted
read-only detail call, as in V34; malformed arguments are rejected before
the ordinal advances. Quarantine requests are **irrevocable** and accepted staging
replies reveal no read outcome. Record each accepted action's query ordinal,
successful detail count, and transcript digest. A missed or wrong-phase
checkpoint, including an early exception, fails at submission with an
explicit `staging_deadline_violations` count and reason. Direct controls
remain available for native consistency checks, but they cannot satisfy a
change-board quarantine slot. More than four original requests, a second
exception, Q-Q current overlap, duplicate Q ID, missing evidence, unsafe
completion, or approved-work collateral remain failures. The final Q/E
effects still use V34 native replay; the deadline gate is an additional
objective control-plane rule, not a planted-ID check.

Several commands in one model response receive their results together after
that response. Prefix proof for a staged control uses only replies delivered
before its response began. In particular, query 31 and the exception in one
response cannot satisfy the final approval-evidence rule.

The initial observation discloses the four change-board slots and query
deadlines. It also publishes these artificial, objectively checkable prefix
evidence rules. The first Q must have six current selectors whose affected
reads are **proven unsafe** by ordinal 20. The second, disjoint Q must have
four newly proven unsafe and two proven approved current selectors by
ordinal 24, with a visible E bundle able to restore the two approved. The
third, disjoint Q must have five remaining proven unsafe and exactly one
unresolved current **Job** selector by ordinal 30. Each Q has exactly six
current and two archive selectors. The unresolved Job's detail is the final
scheduled query; E after query 31 restores it if approved. An action staged
before its required prefix evidence fails at submission even if its final
effects are safe. The scorer calculates statuses from the same accumulated
replies the defender saw, never from native verdict flags. All group IDs,
order, and memberships remain opaque and shuffled.

Catalog witness and filler placement use a private per-run construction key.
The key is absent from visible packets and is fixed across separate processes
in the reference and pilot. Displayed IDs and ordering derive only from public
group membership, so they cannot validate guesses about hidden layout state.
The producer rejects a catalog if public schedule, selector, exception, or
archive motifs uniquely identify an otherwise unproven staged choice.

## Prefix-visible solvability

Build the paired estate and deterministic 31-query schedule first. A new
three-state resolver returns `unsafe`, `approved`, or `unresolved` for each
current selector. A Job selector is classified only for its **renewal** read;
an issued-session selector only for its **active** read. The resolver needs
the applicable source lineage, admitted Job and effective approval streams,
the runtime-read-policy snapshot, and, for an issued session, its Pod→STS
lineage and active plan. Missing
required records mean `unresolved`, never approved. On a complete transcript,
its 24 statuses must match the independent full visible reference and native
read outcomes, including Jobs with one approved and one unsafe phase.

Construct a feasible query order with the paired flip's **only differing
query-workload reply at ordinal 31**. The initial packets and actual first
thirty query replies must be byte-identical across the pair; no flip status
may be inferred from an earlier publication. Retime or regenerate the
schedule without exposing labels, then verify all 30 current details remain
reachable and the prefix counts needed for the three Q slots are met for
both variants. The reference must use only its actual accumulated console
transcript; no second session, producer witness, full episode view, native
labels, or future reply may inform an early action.

The catalog constructor reserves a paired disjoint witness with three
six-current Q groups and one E. It partitions the 16-selector odd unsafe
union plus two approved selectors into a first group of six already-proven
unsafe selectors by ordinal 20, a second group containing four additional
proven unsafe and two proven approved selectors by ordinal 24, and a third
group containing five remaining proven unsafe selectors plus the unresolved
flipped Job selector by ordinal 30. The paired E bundles restore the two
approved selectors in both variants and also the flipped Job selector when
it is approved. Archive fillers keep group sizes eight/six. All reserved
groups are shuffled among ordinary and decoy catalog rounds; construction
labels are never visible.

At each checkpoint, the visible-only reference recomputes resolved statuses
from accumulated replies and selects a Q group satisfying the published
prefix rule. If multiple groups qualify, it may use catalog lookahead, but
never future evidence. The producer accepts a pair only if this reference
commits the same Q sequence under byte-identical prefixes and completes both
variants with their own E choice after the differing final reply. Run the
reference through a serialized transcript-only interface and verify early
choices stay unchanged when future replies and native labels are varied.
Tests must also ensure a guessed Q before its evidence, a Q at the wrong
ordinal, and an E before the final successful detail all fail without a
control-plane verdict leak.

Audit structural rivals using the **combined initial catalog, effective
index, and published query schedule**, not the catalog alone. For each
planted Q, require several shape- and prefix-resolvability-matched decoys
whose authorization facts disqualify them. Run no-detail shortcut baselines
and motif rankings; neither a group ID nor schedule position may select the
winning sequence without reading authorization evidence.

## Gates and measurement

Test missed deadlines, action-before-required-evidence, duplicate and
overlapping Q, wrong exception, action ordering, archive-only actions,
malformed requests, and V34/V33 parity. A separate replay oracle verifies
that accepted staged plans close every unauthorized read and preserve every
approved one. Before model pilots, require 36/36 development reference
passes with exactly 31 queries, four timely requests, complete evidence,
zero invalid actions, zero unauthorized completions, and zero blocked
approved attempts. The development grid must include both members of each
paired estate. Preregister development seeds `109000`–`109011`, pilot seeds
`109100`–`109102` in each of the three controller families, and same-family
invalid-run replacement seeds `109200`–`109211` before any model call. Run
nine valid independent high-effort agentic Astra development cases with
case-local scratch; retire V35 if two or more pass. Freeze the code SHA and a
separate blind protocol only if zero or one pilot case passes. Then require
36/36 untouched post-freeze holdout reference passes on `109500`–`109511`
before opening blind seeds `110000`–`110011` or reserves
`110500`–`110511`, each crossed with the same three families. The blind
criterion remains strict <6/36 exact Astra passes with a twelve-valid-case
early stop at six passes. Transport/format invalidity is replaced, never
counted as a task failure. No GLM call starts until the Astra gate and Cyber
Benchmark's explicit shared Cloudflare release.
